# 校园虾宝 · Campus Shebo

面向大学生多群协作场景的群聊任务管理助手：自动识别群聊中的重要通知，跨群去重汇总，检测通知变更与冲突，经用户确认后通过 Tool Calling 写入日历（.ics）。

> 腾讯第十三届产品经理创造营项目「校园虾宝」的可运行实现。产品设计：王文静。

## 解决什么问题

大学生同时身处多个群（课程群 / 社团群 / 宿舍群 / 班级群），重要通知散落在海量闲聊中：

- **消息过载**：通知被闲聊淹没，容易漏看
- **跨群重复**：同一通知被转发到多个群，反复打扰
- **通知变更**：改期 / 换地点的消息淹没在后续消息里，看到的还是旧信息
- **信息冲突**：不同群传来不一致的时间地点，不知道信哪个

## 产品闭环

```
多群消息 → 通知识别 → 跨群去重汇总 → 变更/冲突检测 → 任务决策
        → 用户确认（附消息原文，Human-in-the-loop）→ Tool Calling → 日历(.ics)
```

## 核心设计

### 1. 双引擎识别层（规则引擎 + LLM，可插拔）

- **规则引擎**：关键词 + 正则，零成本零延迟，覆盖规范表述的通知
- **LLM**（OpenAI 兼容协议，DeepSeek / 智谱 GLM / 通义等均可接入）：负责「下周三社团例会改到下午3点，还是在老地方」这类模糊自然表述，并直接输出**归一化时间**（如 `2026-05-28 15:00`），使相对时间可参与变更比对
- LLM 调用失败自动回退规则引擎，保证服务可用性

### 2. 通知变更与冲突的任务决策

- **新增** → 生成确认卡片，低风险
- **变更**（同一事件、时间不同）→ 生成新旧时间对比卡片；确认后**原位改写**日历事件（同 UID 更新，非追加）
- **冲突**（跨群时间矛盾）→ 高风险卡片，仅提醒、必须人工裁决，Agent 不自动执行
- 事件匹配：操作词剥离（「改期/变更/推迟」）+ 模糊匹配，解决「总结会改期」vs「机器人社本学期总结会」表述不一致的匹配难题

### 3. 跨群去重与消息汇总

同一通知被多个群转发时，自动判定为同一事件并入同一张待确认卡片（不重复打扰），卡片附带全部消息原文（群名 + 发送人 + 原文），确保用户确认的是第一手信息。

### 4. 严格 Human-in-the-loop

任何写日历动作（新增 / 变更）都发生在用户确认之后；拒绝则完全不碰日历。设计原则：**识别可激进，执行必保守**。

## 快速开始

```bash
# 1. 创建虚拟环境并安装依赖（仅需 fastapi + uvicorn）
python3 -m venv .venv
.venv/bin/pip install fastapi uvicorn

# 2a. 规则引擎模式（无需 API key，开箱即用）
.venv/bin/uvicorn app.server:app --host 127.0.0.1 --port 8765

# 2b. LLM 模式（以 DeepSeek 为例，任何 OpenAI 兼容服务均可）
LLM_API_KEY=sk-xxx LLM_BASE_URL=https://api.deepseek.com/v1 LLM_MODEL=deepseek-chat \
  .venv/bin/uvicorn app.server:app --host 127.0.0.1 --port 8765
```

浏览器打开 http://127.0.0.1:8765 ，在左侧三个模拟群聊中发送通知（内置演示脚本可一键触发），观察：

1. Agent 决策流面板：监听 → 识别 → 决策 → 人工确认 → 执行
2. 待确认卡片：附带消息原文，多群转发自动汇总
3. 日历视图与 `calendar.ics` 下载（可双击导入 macOS / 手机日历）

## 项目结构

```
app/
  agent.py    # 核心决策：去重、变更/冲突检测、任务决策、Tool Calling 执行（写/改 .ics）
  llm.py      # 识别层：可插拔后端（LLM / 规则引擎），LLM 输出归一化时间
  server.py   # FastAPI 接口：消息接入、任务确认、状态、ics 下载
static/
  index.html  # 演示界面：多群聊天、Agent 决策流、确认卡片、日历视图
```
